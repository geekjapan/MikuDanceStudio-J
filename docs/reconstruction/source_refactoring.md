## 数值兼容

2026-10-23 的重构替换或移除了应用中的 14 个内联汇编块，以及本地 Bullet 中的 24 个块（含禁用的备选实现）。裸函数已移除；惯性张量计算改用具名矩阵和向量成员。SSE intrinsic 仍用于需要明确单精度运算的阶段。

`LinearMath/btMmdMath.cpp` 隔离了需要 VC9 x86 求值方式的运算，专用编译选项为：

```text
/arch:IA32 /fp:precise /O2 /Oi /GL- /RTC-
```

这些选项只作用于该编译单元。x64 分支保留自己的表达式和编译设置。修改时须保留：

- x87 的扩展精度中间值，以及通过 `volatile float` 实现的原版浮点写回点。MSVC 的 `long double` 为 8 字节，单改类型不能保留扩展精度求值。
- 有序求和的 `noinline` 边界，以及 sqrt/三角函数的局部浮点控制，避免编译器重新结合表达式。
- 调用方的精度控制和舍入模式，以及归一化、惯性和泰勒展开中明确使用单精度的阶段。

### 数值验证

旧实现与新实现并排比较了 32 种运算：每域 100,000 组输入，涵盖有限浮点位模式、中等指数和定向边界值；组合三种 x87 精度与四种舍入模式。边界包含正负零、次正规数、最大有限值、无穷及 quiet/signaling NaN，未观察到输出位差异。

[数学回归](../../tests/mmd_math_test.cpp) 保留每域、每精度/舍入组合 512 组输入，种子为 `0x191234`，使用 xorshift32 和 64 位 FNV-1a 汇总浮点位模式。[golden 数据](../../tests/mmd_math_golden.hpp) 来自旧实现，不能用替换后的实现重新生成。

x87 `FSIN` / `FCOS` 的近似结果会随处理器变化，定向舍入时不能把某台机器捕获的位模式作为跨 CPU 标准。`sinTimes`、`cosine`、`integrateRotation` 因此使用[冻结的旧实现](../../tests/mmd_math_x87_reference.cpp)在当前 CPU、相同精度和舍入模式下生成对照值；其余 29 种运算继续核对原始 golden。历史汇编仅编译进 x86 测试程序，不链接到应用或 Bullet 库。所有 12 种精度/舍入组合仍逐位核对。

另一次旧/新 Bullet 库对照包含地面、16 个盒/球/胶囊、五个 6DoF 弹簧约束、重力和外加扭矩。三种精度各运行 600 步，逐步比较变换、线/角速度与世界逆惯性，1,800 条帧记录一致。这是固定场景的对照结果，不是所有物理场景的等价证明。

## 帧定位

原 x86 定位入口为 `0x004B4260`，x64 对应入口为 `sub_7FF7CB4EBD90`。显示、表情和骨骼轨道仍按该顺序处理；直接定位从各轨道首键开始，返回最后处理的循环计数。帧号按无符号数比较，骨类型保留有符号字节判断。

选择区间末端分支分别清零 `trans[0..2]` 和 `rotQuat[0..2]`，再将四元数 w 设为 1。原先越过 `trans` 数组边界触及相邻成员的写法已消除，保留六次清零效果。

定位和播放推进不能直接共用一个通用 slerp：x64 定位计算 `sin / sin`，推进路径使用倒数乘法；x86 又有独立的浮点写回阶段。四元数夹取值、符号分支和半圆阈值均须保留。

[定位回归](../../tests/model_frame_seek_test.cpp) 对每架构 880 个场景比较完整骨骼状态、表情值、选择区间、IK 标志、返回值及物理通知发生时的状态与顺序。曲线求值和通知使用确定性测试替身，隔离定位算法。修改前实现的 FNV-1a 基线为：

| 架构 | 汇总值 |
|---|---|
| x86 | `705C9B6BD795F475` |
| x64 | `374EC08163B4FB73` |

上述是纯重构时的旧实现基线。后续原版复核修正了 x64 位置插值，当前 x64 期望为 `76B2F2F248828717`：从未拆分的 `24d8844` 实现出发，仅将该处算式改为原版 `mulss` / `addss` 的单精度阶段后取得；没有从重构后的生产实现重新生成。x86 基线不变。测试另以固定浮点位模式检查三个轴的舍入和负零。

命令分发保留资源编号；内部函数按撤销、范围选择、曲线编辑等动作命名。关键帧复制、粘贴和镜像粘贴移入独立模块，全局轨道注册与编辑器命令分开维护。

三个剪贴板命令及十二个注册相关函数与旧版进行了 C++ 语句 token 对照；除注释、格式、已说明的命名和定位类型接口调整外，语句相同。资源消息顺序、剪贴板布局、分配释放配对和选择循环未改动。剪贴板诊断分支另以 `MIKUDANCESTUDIO_DIAG=1` 在两个架构编译通过。

表情帧编辑使用 `MorphKey` 成员替代手算偏移，保留有符号帧偏移判断、链表遍历、字段写入顺序和未涉及的 padding。

## 场景加载

PMM v2 配置段（原 x86 `0x456617..0x45776E`）拆为时间轴、播放、媒体、显示和物理五个阶段。文件读取、状态修改、同步窗口消息和媒体加载仍交错执行；若先解析全部配置再应用，同步消息处理器可能观察到不同状态。

播放设置与媒体阶段共用一个字节暂存值，显示与物理阶段共用另一个。两者跨阶段保留原值，包括短读取时原值不被覆盖的行为。相机参照模式按原版直接读入成员，不占用播放暂存字节。共享缓冲区仍属于单次加载上下文。

五个阶段的语句分别与旧代码对应区间比较；排除上下文字段绑定和 UI 函数更名后，token 一致。模型加载段只修正旧拆分留下的缩进，读取、重试和中止顺序保持不变。
