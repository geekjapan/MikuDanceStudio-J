# 高光顶点生成与插值的因果分离

2026-10-12，针对 [纹理坐标兼容验证](RHI_TEXTURE_COORDINATE_COMPATIBILITY.md) 剩余的 x86 第 5 帧、第 23 次绘制，完成高光顶点生成与插值的独立对照。异常像素仍是 `(509,407)`：DX9 绿通道 109，DX11/DX12 为 108。本次增加诊断和证据检查，没有修改生产着色公式或开启应用替换路径。

结论限于保存的三角形及两个独立几何：相同高光输入经两后端插值时，float32 图像完全相同；能重现原图的顶点输入存在差异。局部视线参与的顶点高光强度计算是下一步定位范围，尚未确定其中哪条指令的舍入产生偏差。

## 测量方法和门禁

入口为 `--model-batch23-spec-origin`，诊断实现位于 `tests/model_specular_origin_fixture.hpp`。保存批次缩减为三角形 1362，原索引 `8049,8064,7452`，保持矩阵、法线、材质和灯光；关闭深度、模板、混合及 Alpha 测试，单独观察高光。诊断 PS 保留原有语义链接，输出 `COLOR1` 到 float32 目标。

DX11 通过 stream output 直接读取共享 measured VS 的 `COLOR1`，没有将高光重新编码进 UV 或漫反射。DX9 固定功能顶点处理没有对应的寄存器捕获接口，因此采用两种可观测输出，并要求它们通过原图重现门禁：

- 单点控制保持原始位置，另做只改变投影 XY 的居中控制。两种点投影的结果相同，但把点观测值用于三角形插值后，无法重现原生图像；该数据保留作失败的测量控制，不作为修复基准。
- 平面着色控制保留原三角形，循环轮换首顶点。每次输出在整个三角形内恒定；将三组值交给共享 `COLOR1` 插值路径后，精确重现原生 Gouraud 高光图像。这组值通过重现门禁，可用于本次因果分离；仍不宣称它们是原生顶点寄存器的直接读回。

共享插值路径使用相同裁剪坐标和高光值，保留完整输出语义；分别覆盖 DX9 VS/PS 2 与 3 链接。另外将相同值经网格 UV 传入原几何路径，检查变换与插值的组合。所有差值统计覆盖整个视口，原生保存三角形覆盖 53 像素；不只检查异常点。其附近 5×5 位置单独写入 CSV。

## x64/x86 实测结果

NVIDIA TITAN Xp，单采样。两种架构重放同一份 x86 场景归档，避免 CPU 场景状态的变化混入 GPU 运算对照。保存几何、程序生成的独立几何、改变法线与高光指数的留出几何各重复三次，每个架构 135 次图像观测。独立／留出几何各覆盖 1416 像素，不根据保存图像拟合输入。

| 控制 | DX9 与 DX11 差异像素 | DX9 与原生图像差异 | DX11 与原 DX11 图像差异 |
|---|---:|---:|---:|
| 保存三角形原高光路径 | 48 | 0 | 0 |
| 同用 DX11 SO 高光顶点值 | 0 | 48 | 0 |
| 同用 DX9 平面着色观测值 | 0 | 0 | 48 |
| 同用 DX9 单点观测值 | 0 | 49 | 47 |
| 独立／留出几何原高光路径 | 0 | 0 | 0 |

共享 COLOR1、网格 UV 控制均两后端零差异，DX11 SO 重现门禁和 DX9 平面着色重现门禁均通过。三次重复的完整浮点图像逐字节一致；两个架构的 CSV、浮点图像、诊断 HLSL 和反汇编一致。

相对通过门禁的 DX9 平面着色值，保存三角形的 DX11 SO 差值为：

| 顶点 | R 的 ULP 差值 | G 的 ULP 差值 | B 的 ULP 差值 |
|---|---:|---:|---:|
| 0 | +4 | +3 | +4 |
| 1 | 0 | 0 | 0 |
| 2 | -4 | -2 | -3 |

ULP 差值为 DX11 float32 位模式减 DX9 位模式，本次值均为正有限数。独立／留出几何没有顶点高光差异。

## 高光强度和颜色乘法

将材质及启用灯光的高光颜色设为全 1，分别使用指数 0、1、2、5；另做关闭 `LOCALVIEWER` 的指数 1、5 控制。保存三角形单位颜色强度的 DX11 SO 相对 DX9 平面着色观测值如下：

| 局部视线 | 指数 | 顶点 0 ULP 差值 | 顶点 1 | 顶点 2 |
|---|---:|---:|---:|---:|
| 开 | 1 | +1 | 0 | -1 |
| 开 | 2 | +1 | 0 | -2 |
| 开 | 5 | +3 | 0 | -3 |
| 关 | 1 | 0 | 0 | 0 |
| 关 | 5 | 0 | 0 | 0 |

原批次指数为 5。将 DX9 单位颜色强度乘回共用的材质×灯光颜色系数，以 float32 舍入，9 个顶点通道全部精确重现原 DX9 平面着色结果；DX11 捕获的强度与系数也精确重现全部 27 个 SO 通道。保存批次的颜色乘法无需额外修正规则。

指数 0 控制也被记录：原生观测略小于 1，DX11 为 1。尚未判定是原生指数处理还是幂函数近似，不能据此引入指数下限。指数 1 的可观测结果也不能当作原生点积直接读回：DX11 捕获的原始点积与 `pow(x,1)` 本身就可能相差 1 ULP。

关闭局部视线后结果一致，说明偏差依赖当前局部视线输入；这不足以单独证明 `normalize(-camera.xyz)` 有错，也不能排除幂函数对特定输入的舍入。还需拆分相机位置、视线归一化、半角向量、点积和幂函数。

## 已拒绝的运算候选

`camera_policyN` 是诊断字段名，实际覆盖下列顶点算术候选；它们没有进入共享生产着色器：

| 编号 | 变化 | 保存几何结果 |
|---|---|---|
| 1 | world、view 各列按已有 fused 点积计算 | 原差异不变 |
| 2 | 先以分离 float32 运算组合 world×view，再做 fused 点积 | 仍有 46 个差异像素；相对原 DX11 又改变 52 个像素 |
| 3 | 高光法线与半角向量使用 fused 点积 | 原差异不变 |
| 4 | 灯光先归一化，再乘 view | 原差异不变 |
| 5 | 局部视线以 fused 长度平方和 rsqrt 归一化 | 原差异不变 |
| 6 | 半角向量以同样方式归一化 | 原差异不变 |
| 7 | 灯光方向乘 view 改用已有 measured 法线点积 | 原差异不变 |

没有候选满足原生零差异，不能用像素计数略有改善作为修复依据。`vertex_stages.csv` 另存 DX11 的相机坐标、有效法线、灯光方向、视线、半角向量、点积、幂结果及颜色系数；这些是显式着色器观测，不是原生隐藏指令的测量。

## 复现和证据

输出目录必须尚不存在。对 x64 使用对应构建产物和另一个新目录：

```powershell
build-x86/build/Release/rhi_d3d9_replay_conversion_test.exe `
  --model-batch23-spec-origin exports/texture-fma-live-audit-x86/prefix.131316.3 `
  exports/specular-origin-example-x86 509 407 1362

python tools/analyze_specular_origin.py `
  --input exports/specular-origin-example-x86 `
  --compare exports/specular-origin-example-x64 `
  --output exports/specular-origin-example-analysis.json
```

最终证据目录为 `exports/specular-origin-final-x86-6controls/` 和 `exports/specular-origin-final-x64-6controls/`；分析为 `exports/specular-origin-analysis.json`。分析器检查三次完整性、全部 15 种模式、六种单位颜色控制、跨架构字节一致以及双侧原图重现门禁。实际 PMM 归档属于本地验证素材，本命令不作为缺失素材时自动跳过的 CI 验收。

本次回归 x64/x86 各 6/6 通过：DX9 转换的无界面、硬件及 WARP 控制，共享裁剪深度、法线精度、纹理 FMA 独立控制。日志为 `exports/specular-origin-regression-x64.log` 和 `exports/specular-origin-regression-x86.log`。Python 编译检查、证据分析、工作区 `git diff --check` 及新增文件空白检查通过。
