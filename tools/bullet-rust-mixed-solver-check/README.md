# Shared Bullet solveGroup parity

The measured macARM profile has a bounded arithmetic NaN limit. Case 71, second scalar solve, has exactly 1,948 differing fixed-slot delta words. Each native word is `7fc00000` and its Rust counterpart is `ffc00000`. All other words and final stdout match. The check reports `PASS_SOURCE_DEFINED_ARITHMETIC_OBSERVATION`, not universal raw bit parity. The exact paired capture hashes and every case, step, event, field, offset and value pair are frozen in `profiles/macarm-appleclang21-rust1.95.json`. Each stream must match its own frozen capture. Any unlisted difference, count, field, value, source, host or compiler profile fails. The comparator performs no NaN normalization.

Run from the checkout with the pinned Rust toolchain installed.

```sh
python3 tools/bullet-rust-mixed-solver-check/check.py --out-dir /tmp/bullet-mixed --mutations
python3 -m unittest discover -s tools/bullet-rust-mixed-solver-check -v
```

`GroupSolver` owns one companion table, solver body pool, joint rows, normal rows and friction rows. Contact setup only builds rows into that pool. The standalone joint and contact replays use the same owner with the opposite input slice empty. `writeback` consumes the owner. The world API still uses native Bullet.

The oracle calls the actual native `solveGroup` with joints and manifolds simultaneously. Python serializes inputs before either implementation constructs objects. Constructors never draw random values. Each of 96 complete scenarios runs twice. Modes 260 and 4 use identical scenario shapes. The corpus includes ground contacts, 3 and 8 body chains, duplicate-pair manifolds, input permutations, static bodies with nonzero inertia, nonzero-mass kinematic bodies, nonunit and zero factors, signed zero, nonidentity bases, 1 to 4 points, threshold equality and adjacent values, empty and filtered groups, restitution lifetime 2 and 3, seeded normal and lateral impulses, reversed friction bounds and joint motor bounds, and lazy zero-row callback registration. Large penetration exceeds the normal row's nominal upper bound. The final eight scenarios per mode integrate supported dynamic bodies and refresh sphere-plane points between solves. This test adapter never increments point lifetime.

The ordinary native build and a build with observation hooks use the same flags and must produce identical stdout bytes. Hooks change only a copied source file in the output directory. Native source, frozen joint profiles and frozen contact fixtures stay unchanged. Native math uses the existing `det_math.h` and `mds-crtmath`, including SSE emulation on ARM. There is no second impulse algorithm in the oracle.

The runner retains exact commands, compiler and Rust target information, effective native macros, input and source hashes, frozen fixture hashes, the observer diff, original/native/Rust stdout, full native/Rust traces, branch counts and each mutation's first behavioral difference. A mutation must compile and run successfully before an output difference counts. Parser, hash or compiler failures are failures of the check.

## Trace schema version 1

Each trace line starts with five decimal fields, `case`, `step`, `kind`, `iteration`, and `index`. Every remaining field is one lowercase eight-digit hexadecimal word. Float words are raw IEEE-754 bits. Negative zero, NaN signs and payloads, infinities and reversed limits are compared without normalization.

Kinds are 0 for completed setup, 1 and 2 for joint before and after, 3 and 4 for normal before and after, 5 and 6 for eligible friction before and after, 7 and 8 for obsolete callback before registration and after invocation, 9 for skipped friction, 10 for completed writeback before native cleanup, and 11 and 12 for each solver body's writeback before and after. Setup and finish use iteration and index -1. Body writeback uses iteration -1 and its pool index. Other events use iteration 0 to 9 and the native input row or joint index. A callback's joint identity and A/B original IDs come from the serialized joint table. Its pre-registration IDs come from companion mappings, with mass-zero mapping to fixed slot 0. Unregistered dynamic bodies have companion `ffffffff` until that callback.

Every event contains the following complete snapshots in this order.

1. Pool count, then 19 words per solver body. Fields are original body index or `ffffffff`, vector inverse mass, angular factor, delta linear velocity, delta angular velocity, push velocity and turn velocity.
2. Joint row count, then 29 words per row. The common first 23 words are body IDs, contact normal, both angular Jacobians, both angular components, diagonal inverse, RHS, CFM, lower bound, upper bound and applied impulse. Joint tails are applied push impulse, friction, penetration RHS, consecutive-row metadata, friction index and null-contact-point flag.
3. Normal count, then 29 words per row. The common fields are followed by manifold and point indices, friction, applied push impulse, penetration RHS and friction row index.
4. Friction count, then 29 words per row. The common fields are followed by normal index, applied push impulse, friction, penetration RHS, consecutive-row metadata and null-contact-point flag. Native initializes the unused friction penetration RHS and consecutive-row metadata with `ffffffff`; those exact words are retained.
5. Original body count, then 71 words per body. Fields are companion ID, world transform, linear and angular velocities, linear and angular factors, scalar inverse mass, local inverse inertia, world inverse inertia tensor, accumulated force and torque, material friction and restitution, interpolation transform and velocities, gravity acceleration, damping values and static/kinematic flags.
6. Manifold count, then point count for each manifold, then 29 words per point. Fields are local A/B positions, world A/B positions, normal, distance, combined friction/restitution, normal impulse, lateral impulses, lifetime, initialized flag and both lateral directions.

Transforms are three basis rows followed by origin. All vectors have three components. Counts and indices use unsigned words; absent indices use `ffffffff`. Native padding, vector lane 4, pointer addresses and demonstrably unwritten fields are excluded. The solver body's `m_friction` and a normal row's consecutive-row metadata are never initialized on these native paths. They are not read. Joint metadata is defined by native zero initialization, so it is included.

Native body writeback events come from the actual native calls. The Rust diagnostic assembles the expected intermediate writeback snapshots from the actual consumed product writeback's before/final values and unique original-body mapping. It copies each final velocity into its expected pool-order position, without reimplementing the addition or impulse arithmetic. Final product output is independently compared to native stdout. The main product solver stores no trace buffer.

`trace.py` validates all IDs, mappings, raw word widths, boundaries, event order, ten iterations, friction eligibility and full record consumption. Coverage counters come from observed snapshots and branches. Missing required branches fail. Existing frozen profiles remain separate strict gates. `observation.py` separately verifies the bounded paired observation without weakening the raw comparator or its finite, signed-zero, infinity, status, branch and copy checks.

## Numerical limits

Zero-inertia angular rows deliberately generate unordered arithmetic. SIMD's upper-mask behavior and scalar NaN propagation remain distinct. Existing frozen joint properties are limited to their named zero-inertia cases and supported host profiles. The mixed oracle compares generated values as raw bits on the same host and inventories every disagreement. In case 71, the first scalar solve generates identical positive quiet NaNs in normal impulses. The second setup reads those same bits, negates the B-side impulse and accumulates the normal warmstart into fixed slot 0. The first difference occurs in those arithmetic additions and multiplications. Source operations and factors match. A same-flags native boundary probe confirms that copying `7fc00000` preserves it and unary negation yields `ffc00000`. The 1,948 differences propagate only through fixed-slot linear and angular deltas during that second solve. No original body owns the fixed slot, and no final body, row impulse, contact point, event order or branch result differs. The paired profile freezes the observed distinction without imposing a NaN operand-priority rule on product arithmetic. It never treats all NaNs as equal or substitutes a frozen profile for a live comparison. Unsupported alternate native non-SSE profiles are not tested.

The workflow configures full same-host comparisons and mutations on Windows x64, Apple Silicon macOS, Linux x64 and Linux ARM64. A configured or queued workflow is not execution evidence. World replacement, activation, islands, broadphase and native dependency removal are outside this slice.

Native companion fields persist between solveGroup calls within a world step because native writeback leaves their reset commented out. This slice uses explicit fresh per-call input companion state, as do its frozen direct-call fixtures. A nonzero-inverse-mass kinematic body shared across separate islands requires separate native World scheduling characterization. This implementation does not pre-register bodies, union kinematic islands or silently reset native companions to choose a World policy.
