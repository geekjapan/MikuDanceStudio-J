# 饰品第 65／66 次绘制的深度测量

2026-10-07，NVIDIA TITAN Xp，硬件设备，单采样、RGBA8／D24S8。
使用真实 `sample.pmm` 的已保存 x64 输入，在 x64、x86 测量程序中重放同一份数据。
应用仍使用原 DX9 路径；此次只增加测试工具，没有修改着色器、深度偏移或渲染开关。

**四个 Alpha 差异源于第 65 次绘制产生的不同深度历史。**
去除纹理及 Alpha 测试后，两套 API 的独立批次深度阈值相同；
保留完整历史时，第 65 次绘制后的颜色图像相同，但深度已经不同。
原始 `GreaterEqual, ref=1` 的 Alpha 测试在四个位置表现不同：DX9 丢弃片元，DX11 放行。
这解释了第 66 次绘制的遮挡差异，但尚未确定 Alpha 的采样、运算或量化究竟在哪一步产生偏差。

## 测量方法与范围

素材来自 `exports/cpu-accessory-control-audit-x64/prefix.98444`，
加载前要求 manifest 为 `READY nativeExact=1`，目标为单采样 D24S8。
两个批次使用完全相同的四顶点、六索引网格，世界矩阵分别取捕获值。
目标 1920×1080，视口 `(565,25,1032,774)`，深度范围 `[0,1]`。

测试 `tests/accessory_depth_threshold_fixture.hpp` 提供两种入口：

- `--accessory-depth-thresholds`：六个坐标、两个批次、原始矩阵变换与相同裁剪空间顶点，共 24 次独立深度阈值测量；再测第 65／66 次绘制后的完整前序历史，共 12 次测量。
- `--accessory-alpha-depth-controls`：仅改变第 65 次绘制的 Alpha 测试参考值，扫描关闭测试及参考值 0、1、2、3；另用中间深度标尺验证深度写入后果。

阈值用常量深度标尺的 `Less` 二分搜索得到，并用 `Equal` 与相邻 float32 值复验。
每组测量在阈值处新提交三次，要求判定稳定。
独立常量平面另做 90 个校准检查，覆盖 `Less`、`Equal`、`LessEqual`。

完整历史测量保留从清屏开始的全部前序绘制、纹理 Mip、Alpha 测试与深度／模板状态。
标尺前增加仅写颜色的红色覆盖面，关闭深度测试、深度写入和模板测试；
它让标尺通过与否可辨识，不改变待测深度历史。
各坐标使用独立小标尺，避免相邻验证坐标的参考深度互相覆盖。

这是**通过深度比较测得的阈值**，不是原始 D24 深度面的读回。
表中的 D24 单位为阈值乘 `2^24-1` 后的整数差。
DX11 顶点采用生产兼容着色器与常量，通过 stream output 观察；
其 32 个 XYZW 分量与 CPU 顺序矩阵组合、融合点积预测逐位一致，重复三次稳定。
相同裁剪空间控制把这些顶点提供给两个 API，**不代表已经捕获 DX9 固定功能顶点输出**。

## 独立批次结果

六个位置上，DX9 与 DX11 的独立深度阈值全部一致。
原始变换与相同裁剪空间控制的阈值也相同。
第 66 批次相对第 65 批次的深度标尺间距如下，正数表示更远：

| 坐标 | 阈值间距，折算 D24 单位 |
|---|---:|
| (1040,725) | 2 |
| (1097,740) | 2 |
| (1136,757) | 1 |
| (1163,776) | 1 |
| (1041,725)，验证点 | 2 |
| (1097,741)，验证点 | 2 |

只绘制无纹理、无 Alpha 测试的两个批次时，两套 API 都由第 65 批次遮挡第 66 批次。
关闭后一批次深度测试后，两套 API 都显示后一批次；三次重复一致。
因此，这个独立控制没有证明深度平面建立或量化存在跨 API 偏差。

## 完整历史结果

第 65 次绘制后的颜色图像为零像素差异，第 66 次绘制后出现四个 Alpha 差异，RGB 相同；
每个边界三次重复得到相同结果。

| 坐标 | 第 65 次后 DX9 阈值 | 第 65 次后 DX11 阈值 | DX11−DX9，D24 单位 | 第 66 次后 DX11−DX9 |
|---|---:|---:|---:|---:|
| (1040,725) | 0.979152500629425 | 0.978884696960449 | −4493 | −2 |
| (1097,740) | 0.978162288665771 | 0.977881729602814 | −4707 | −2 |
| (1136,757) | 0.977039992809296 | 0.976745069026947 | −4948 | −1 |
| (1163,776) | 0.975785672664642 | 0.975474655628204 | −5218 | −1 |
| (1041,725)，验证点 | 0.979152500629425 | 0.979152500629425 | 0 | 0 |
| (1097,741)，验证点 | 0.977814853191376 | 0.977814853191376 | 0 | 0 |

四个异常位置上，DX11 的第 65 次后阈值等于独立第 65 批次的阈值，
DX9 则保留更远的历史深度。
第 66 次后，DX9 阈值更新到独立第 66 批次的阈值；DX11 仍保留第 65 批次的阈值。
因此四个位置的 DX9 Alpha 变为 127，DX11 保持 0。

这是“颜色没有变化，深度写入已经不同”的实际案例：
仅逐绘制比较颜色图像会把首个可见差异记在第 66 次绘制，遗漏第 65 次的历史分歧。

## Alpha 测试控制

保留第 65 批次的原始几何、矩阵、灯光、纹理，关闭深度、模板和混合，
用黑色背景区分丢弃与放行。四个异常位置得到相同判定：

| Alpha 测试 | DX9 | DX11 |
|---|---|---|
| 关闭 | 放行 | 放行 |
| GreaterEqual，ref=0 | 放行 | 放行 |
| GreaterEqual，ref=1（原始状态） | 丢弃 | 放行 |
| GreaterEqual，ref=2 | 丢弃 | 丢弃 |
| GreaterEqual，ref=3 | 丢弃 | 丢弃 |

命名修正：捕获状态 `D3DRS_ALPHAFUNC=7` 对应 `D3DCMP_GREATEREQUAL`；
初稿误写为 Greater，测量数据和程序实际执行的状态未变。

验证点 `(1041,725)` 在 ref=1 时双方都丢弃，`(1097,741)` 双方都放行。
每组重复三次，x64／x86 的全部 96 行控制数据相同。
测试最终保存的是目标 RGBA，不能将它当作 Alpha 比较时的高精度输入值。

在完整第 65 次历史后，向 `(1040,725)` 投放深度为
`(0.97888469696044922+0.97915250062942505)/2` 的标尺：

- 保留原始 Alpha 测试：DX9 标尺通过，DX11 被遮挡。
- **只关闭第 65 次绘制的 Alpha 测试**：双方标尺都被遮挡。

该控制验证 Alpha 丢弃行为会改变这里的深度历史；它不是修复方案。
不能通过关闭 Alpha 测试、禁止深度写入或增加深度偏移来通过验收。

## 重现与证据

先构建 `rhi_d3d9_replay_conversion_test`，以下命令分别将 `x64` 改为 `x86` 运行。
输出目录必须不存在；硬件测试串行执行。

```powershell
build-x64/build/Release/rhi_d3d9_replay_conversion_test.exe `
  --accessory-depth-thresholds `
  exports/cpu-accessory-control-audit-x64/prefix.98444 `
  exports/accessory-depth-history-x64

build-x64/build/Release/rhi_d3d9_replay_conversion_test.exe `
  --accessory-alpha-depth-controls `
  exports/cpu-accessory-control-audit-x64/prefix.98444 `
  exports/accessory-alpha-depth-x64

python tools/analyze_accessory_depth.py `
  exports/accessory-depth-history-x64 exports/accessory-depth-history-x86 `
  --alpha-x64 exports/accessory-alpha-depth-x64 `
  --alpha-x86 exports/accessory-alpha-depth-x86
```

每个架构：24 次独立阈值测量、12 次完整历史测量、32 个顶点分量、90 个标尺校准检查；
独立测量 548 次提交、3288 个坐标判定，历史测量 128 次提交、768 个坐标判定。
八份 CSV 和 Alpha 控制数据在 x64／x86 完全相同，分析结果为
`exports/accessory-depth-analysis.json`。
CTest 的 `rhi_d3d9_replay_conversion` 与 `rhi_shared_clip_depth_hardware` 在两个架构均通过 2/2。

这是同一份 **x64 捕获输入** 的跨架构重放结果，不改变先前 x86 自身场景验收通过的记录。
本轮深度测量对照 DX9／DX11，未新增 DX12 深度测量；
此前 DX12 在同一四个坐标的颜色差异记录仍保留。
真实素材与捕获数据放在忽略目录，未添加进仓库。
测量程序返回成功仅表示测量完成，完整场景零差异验收仍未通过。
