# Real PMM independent batch: DX9 / DX11 offscreen comparison

The first captured PMM material batch passes strict DX9 fixed-function versus
DX11 hardware shader comparison on x64/x86. The application renderer remains
on its legacy DX9 path. This is isolated batch acceptance, not a full-frame,
full-model, renderer replacement or a cross-vendor guarantee.

Follow-up [larger-batch scene history acceptance](RHI_SCENE_HISTORY_COMPARISON.md)
adds an actual-application reference and records source vertex-processing mode.
It establishes floating diffuse for the hardware source. The byte profile below
describes the original software-vertex replay experiment; it is not a universal
DX9 compatibility setting. Current capture schema is 5; historical evidence
retains the schema version used at the time.

## Input and capture boundary

The local source is MikuMikuDance v9.32 `UserFile/sample.pmm` (PMM v1). It loads
through the existing missing-model relocation GUI using `Dammy_Bone.pmd`.
At frame 5 the independent batch is model slot 2, material 10 of
`Miku_Hatsune_metal.pmd`: first index 63381, 24 indices / eight triangles,
32-byte position/normal/UV vertices and uint16 indices. Existing eligibility
checks exclude IK, physics, grants and MME effects.

`MDS_RHI_REAL_BATCH_CAPTURE=1` requests diagnostic export before the original
draw. It captures the deformed mesh, captured material/matrices/directional
lights, logical texture cascade, native raster/blend/stencil/sampler states,
viewport size, sample count/quality and bound texture RGBA. Captured exposed
levels are retained; native auto-generated mipmaps are explicitly marked and
regenerated by each replay backend. No original model or texture is checked in.

`real_batch.capture` is a local, versioned native diagnostic transport. It
contains a trivially copyable `MaterialShaderInputs` object and is **not** a
portable scene/resource file format. The reader checks magic, version, input
size, dimensions, lengths, vertex finiteness and selected index ranges. It
rejects unsupported fog, sRGB writes, non-solid fill, UV1, clipping planes,
depth bias, scissoring and two-sided stencil. The fixed-FVF source has no
vertex colors, so material values supply lighting inputs. Different vertex
formats need their own source-selection contract before acceptance.

The GUI runner sets capture-only mode and checks
`actualAdapterApplied=0` in the existing same-frame report. Old DX9/RHI-DX9
probe comparisons still execute diagnostically; they do not replace the actual
application draw. DX11 runs only in the standalone replay executable.

## Shader transport and formulas

`model_material_vertex.hlsl` uses row-major, row-vector world/view/projection
matrices and the captured inverse-transpose normal matrix. It applies the DX9
pixel-center adjustment before DX11 rasterization. Camera-space normals feed
the captured texture matrices for Toon/Sphere; ordinary Base uses mesh UV0.

The fixed-FVF directional lighting subset computes emissive plus global/light
ambient, material diffuse times light diffuse times `max(N dot L,0)`, and a
separate Blinn half-vector specular term with material power. Normals normalize
only when requested; directional light and half vectors normalize explicitly.
Local viewer uses the camera-space position. Diffuse Alpha is retained. The
pixel shader combines Toon/Base/Sphere and adds the separate specular RGB after
texturing. Point/spot lights, vertex color inputs, UV1 and other passes are not
covered by this subset.

`ModelVertexConstants` makes the 1088-byte HLSL buffer layout explicit.
The production shader, not a separate test-only shader, runs through a WARP
VS/GS stream-output test. Known front/back/tangent normals exercise ambient,
diffuse, nonzero specular, normal normalization, transformed camera-normal
coordinates, UV passthrough, matrix orientation and pixel-center adjustment.
Both floating diffuse and the byte compatibility variant are checked against
independent expected values. The real material's specular RGB is zero; the
stream-output assertions therefore provide the nonzero specular check, not
real-material specular pixel acceptance.

## Two explicit compatibility settings

The initial MSAA comparison failed at ten edge pixels (maximum channel error
9) even when both materials were replaced by constant black. DX9's values
matched sRGB sample combination, while DX11 UNORM resolve produced linear byte
averages. For example, background 48 with one covered black sample out of eight
resolves to 45 on DX9 and 42 with DX11 UNORM. Changing **resolve format** to
`R8G8B8A8_UNORM_SRGB` makes the flat diagnostic and real material identical.
The DX11 color target is typeless with an UNORM render-target view; writes and
sampling retain the captured non-sRGB semantics. Only resolve interpretation
changes. This is an explicit tested profile on this driver, not an inferred
universal DX9 rule or a global RHI default.

The x86 additive Sphere case initially had one blue-channel difference of 1.
Quantizing vertex diffuse to `floor(color*255+0.5)/255` before interpolation
removes it. This is selected by `--vertex-byte`; ordinary floating lighting
remains separately testable. The profile quantizes all diffuse channels using
the same rule; no material-specific color offset or acceptance tolerance is
applied. More materials/devices must establish where this profile applies.

The accepted replay profile is therefore `--vertex-byte`, plus
`--msaa --srgb-resolve` when using captured MSAA. Raw/default replay, flat-color
isolation and optional centroid experiments remain available. Centroid did
not remove the original MSAA discrepancy and is disabled in acceptance.

## Results and practical limits

The GPU is NVIDIA TITAN Xp (`10de:1b02`). The test verifies matching DX9/DX11
vendor/device IDs before hardware comparison. These are local Windows results;
no new Linux/macOS GPU test is claimed.

| Captured configuration | x64 single sample | x64 8x MSAA | x86 single sample | x86 8x MSAA |
| --- | --- | --- | --- | --- |
| Toon + original Base texture | Exact | Exact | Exact | Exact |
| Toon + Base + multiply Sphere | Exact | Exact | Exact | Exact |
| Toon + Base + additive Sphere | Exact | Exact | Exact | Exact |

The Sphere variants use the existing GUI test's authored Sphere fixtures and
temporary material references on the real PMM geometry; they are controlled
configurations, not untouched original Sphere references. Original PMM/model
files are unchanged. The previously accepted Base/Toon preparation continues
to compare against actual native textures before capture.

Each replay uses the captured canvas size and original frame geometry on a
uniform `(48,48,48,255)` background, with fresh D24S8 depth/stencil, identical
blend/depth/stencil rules and matching sample quality. It does **not** import
the preceding scene's color/depth history. Both targets must differ from the
clear image. The batch is small: only a few single-sample pixels and roughly
8–10 resolved MSAA pixels change in the tested viewports. This is useful as
the first bounded batch, but a larger eligible batch and shared scene history
are necessary for broad acceptance. Viewport sizes can differ between GUI
captures; each architecture compares its own exact input on both APIs.

The two full GUI CTests pass without skips (one per architecture, each runs
three captures and six replay comparisons). Six focused shader tests also pass
on each architecture. All twelve final target pairs are independently checked
against the report counts/maxima; the application adapter stays off.
Final evidence is under `exports/rhi-real-dx11-{x64,x86}-final`, with captures,
source/snapshot reports and `profile-single` / `profile-msaa` RGBA targets.
`exports/rhi-real-dx11-acceptance.json` records the verified summary.
The capture directories are ignored because they contain external resource
bytes. The portable core has not changed, so prior resource CI remains its
evidence; these added native tests are local Windows evidence only.

## Reproduce

```powershell
cmake --build build-x64/build --config Release --target MikuDanceStudio pmm_v1_relocation_gui_test rhi_d3d9_parity_test rhi_d3d11_real_batch_test rhi_d3d11_model_vertex_test
$env:MDS_PMM_GUI_FIXTURE='C:\Users\jstzw\Downloads\MikuMikuDanceE_v932\UserFile\sample.pmm'
$env:MDS_PMM_RELOCATE_MODEL='Dammy_Bone.pmd'
ctest --test-dir build-x64/build -C Release -R '^rhi_real_d3d11_batch_gui$' --output-on-failure
ctest --test-dir build-x64/build -C Release -R '^rhi_d3d11_(model_vertex|material_pixel)' --output-on-failure
```

Repeat with `build-x86/build`. Missing external fixtures/device return 77;
actual acceptance above ran, without skips. Pixel differences return 2 and
must not be converted to tolerance-based success.

```powershell
build-x64/build/Release/rhi_d3d11_real_batch_test.exe --vertex-byte --msaa --srgb-resolve exports/rhi-real-dx11-x64-final/model_textures_combined_add/real_batch.capture exports/rhi-real-dx11-x64-final/recheck
python tools/analyze_rhi_real_batch.py exports/rhi-real-dx11-x64-final/recheck --images
```

The analyzer recomputes pixel/channel differences, maximum error and changed
pixels from raw bytes and records the first difference. Optional Pillow PNG
exports include full DX9/DX11 targets and a nearest-neighbor crop ordered
DX9, DX11, absolute difference. CTest requires no Pillow.
