# Single-sample scene prefix with the combined normal/material candidate

The subsequent [ground geometry implementation](RHI_GROUND_GEOMETRY.md) removes
the conversion block described below. Fresh ground-enabled captures contain
51 draws and 195 events with exact native reconstruction. Their DX11 image
gates still fail; the table there records both architectures and independent
ground batch results. Earlier no-ground measurements below are retained.

Fresh `sample.pmm` application captures now export the complete selected prefix,
including immutable resource bytes, prepared mip levels and every native
submission-boundary image. A separate DX11 diagnostic replays each boundary
with the [validated normal/material combination](RHI_NORMAL_TRANSFORMS.md).
The larger x64 viewport **fails** this image gate; the smaller x86 viewport
passes all fifty boundaries. Neither result enables an application backend.

## Capture and replay contract

`MDS_RHI_PORTABLE_PREFIX_EXPORT=1` is a new default-off diagnostic setting. It
works with the existing portable recorder and per-draw trace. After native
reconstruction, it exports every captured draw and its before-draw BGRA image,
the final native image and a manifest with target/clear metadata, pass names,
event count and the first blocked draw/sequence/reason. A blocked or incomplete
capture remains explicitly `BLOCKED`; it cannot become a ready stream by
omitting unsupported commands. This is an extension of the existing private
native text/byte diagnostic, not a durable portable scene serialization.

`tests/scene_prefix_fixture.hpp` independently rebuilds the portable stream
from these snapshots. It validates the whole stream before replaying any
prefix. Every boundary starts from the recorded clear and replays prior draws,
including depth/stencil/blend history; no intermediate image replaces that
history. All resource versions remain CPU-owned. The combined candidate is
available only through the test executable's separate DX11 adapter factory.

At each boundary, a fresh DX9 HAL hardware-VP reconstruction is compared with
the actual application image, then the diagnostic DX11 image is compared with
that same image. Native upload in this test now supports recorded XRGB8 and
DXT block rows as well as ARGB8; native autogenerated mip filtering is retained.
The captured model textures exercise the XRGB8 path. The final DX11 prefix is
repeated and must remain exact relative to its own previous image.

The known region is the original scene viewport. Pixels outside that region
are unspecified and are not compared. The stream is single-sample RGBA8/D24S8.
The selected boundary is before material 13, so that material's own submission,
later outlines/accessories and the remaining frame are outside this acceptance.

## First failing accessory control

Draw 4 is an indexed 1,162-triangle untextured accessory batch, FVF 274,
stride 32, index start 1008 and vertex range 40..13327. Its unchanged native
original/repeat images must equal the application boundary after draw 4.
Thirteen controls keep actual mismatches visible:

| x64 archived inputs | Different pixels | Maximum channel delta |
|---|---:|---:|
| Original / repeat / selected draw alone | 244 | 59 |
| Depth test and writes disabled | 223 | 1 |
| Stencil disabled | 244 | 59 |
| Specular disabled | 243 | 58 |
| Normalization disabled | 23 | 6 |
| Lighting disabled | 0 | 0 |
| Before selected draw | 0 | 0 |
| Only viewport changed to `(274,25,670,503)` | 0 | 0 |
| Smaller viewport, depth disabled | 0 | 0 |

The x86 executable runs the **same x64 archive** and reproduces every control
image and CSV byte-for-byte. All 27 artifacts (26 images and one CSV) have
matching SHA-256 hashes. Thus the observed difference is not an executable
bitness discrepancy on these fixed inputs. Changing only the viewport removes
the difference; geometry, transforms, material, light and other states remain
fixed. This indicates a viewport-size-related raster/depth/interpolation
boundary, without establishing a specific driver arithmetic formula.

Disabling depth removes the large deltas but retains one-byte shading or
interpolation differences. The first draw alone still fails, so the preceding
three draws are not a necessary cause. Disabling lighting produces uniform
white for this FVF and can hide changed surface selection; its zero image does
not prove that geometry/depth already agree. No production ordering, depth
comparison, viewport or normalization behavior is changed to pass a control.

## Actual ground coverage and explicit blocking

The original sample prefix contains no ground draws. A separate GUI mode,
`MDS_RHI_GUI_GROUND=1`, changes only the copied temporary PMM's ground-grid byte
before application loading. It derives the configuration boundary with the
portable PMM parser and reparses the modified copy. Original source assets are
preserved. A menu toggle after capture is insufficient and is not used as
evidence of ground coverage.

Both architectures capture 51 native draws with this temporary setting:
ground first, then the original 49 draws. Native reconstruction is still exact.
Portable conversion deliberately blocks at draw 1 / event 2 with
`unsupported_geometry_layout_or_base`:

1. FVF 66 / stride 16, indexed `LineList`, 45 line primitives.
2. FVF 66 / stride 16, nonindexed `TriangleList`, two plane primitives.

The current portable model replay subset requires indexed triangles, so these
ground commands are outside its contract. Both GUI and independent replay
return 31. The latter rejects the blocked manifest before DX11 device creation
or submission. Ground has been measured as a supported native pass and an
explicitly unsupported portable pass, not claimed as an accepted DX11 image.

The runner requires a fresh output directory, preserves previous evidence and
does not accept a stale manifest after a failed application run. Exit 77 is
unavailability, 31 is explicit blocking and 32 is image failure. Native/GPU
creation failures remain failures, not skipped image acceptance.

The current captures are `exports/scene-prefix-normal-{x64,x86}/`, with
`candidate/trace.csv`, every boundary image, `isolated.csv`, differing draw-alone
image pairs, summary and analysis JSON. First accessory controls are under
the x64 archive's `first-controls/` and `first-controls-x86/`; their hash proof
is `exports/scene-prefix-shared-input-architecture.json`. Ground evidence is
`exports/scene-prefix-ground-fixture-{x64,x86}/`. `tools/analyze_scene_prefix.py`
independently audits every geometry/texture hash, prepared mip, state, matrix,
pass label and saved image difference against the application recorder.

The final focused regression passes **13/13 CTests on x64 and 13/13 on x86**:
native/Hardware/WARP mip capture, native-to-portable conversion, Hardware/WARP
shadow images and shadow oracle, viewport and portable replay validation.
Both application and GUI harness builds also pass. Logs are
`exports/scene-prefix-focused-{x64,x86}.log`. These regression successes do not
override the failed x64 real images or the blocked ground conversion.
