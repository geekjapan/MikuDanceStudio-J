# DX9 recorder to owned model replay snapshots

The subsequent [viewport contract](RHI_VIEWPORT_CONTRACT.md) adds offset/partial
viewports and explicit initialized-region bounds. Target rejection and passing
native graphics counts below describe the earlier capture milestone.
The later [null-texture control](RHI_DX9_NULL_TEXTURE.md) establishes and converts
canonical null-stage termination; it records Hardware and WARP results separately.
The subsequent [mip capture milestone](RHI_DX9_MIP_CAPTURE.md) materializes
hidden autogenerated levels. With its diagnostic switch enabled, fresh x64/x86
PMM captures convert 19 accessory draws, then stop at projected-shadow draw 20.
Earlier milestone results below are retained as historical evidence.

The optional diagnostic recorder now converts supported native DX9 draw
snapshots into `ModelReplayStream`. The conversion is CPU-only and preserves
the native recorder's existing DX9 state-block replay. Application rendering
still uses DX9. This does not mark the complete scene replay capability ready.

## Boundary

`D3D9ReplaySnapshot` holds owned geometry and mip bytes plus documented native
state values, matrices, material and directional lights. It carries no COM
resource or state-block pointers. The native recorder's `Draw` extends it with
the private references needed for its original DX9 comparison.

`AppendD3D9ReplaySnapshot` converts one draw transactionally. It decodes native
blend, depth, stencil, sampler and texture-cascade states; copies geometry;
swizzles A8R8G8B8/X8R8G8B8 mip pixels into RGBA; and publishes new versions of
logical geometry/texture slots before the draw. Older snapshots remain intact.
It checks DX9 MinVertexIndex/NumVertices constraints as well as portable index
ranges. Conversion failure leaves the caller's stream unchanged. The recorder
then records an unsupported event and stops admitting further portable draws.

The first subset accepts indexed triangle lists with XYZ/normal/UV0, 32-byte
vertices, zero stream offset/base vertex, 16/32-bit indices, directional lights,
the existing three-stage Modulate/Add cascade, and captured uncompressed mip
chains. Without lighting, this FVF's absent COLOR0 produces white diffuse,
independent of D3DMATERIAL9; the converter explicitly preserves that behavior.

Compressed formats, autogenerated mips, LOD overrides, fog, bias, scissor,
non-directional lights, noncanonical layouts and unsupported fixed-function
operations block conversion. Semantic roles attached to generic native stages
describe their cascade slots, not proof of a PMM resource's authored Toon/Sphere
role. Native stage coordinates/operations are the source of shading behavior.

The initial target must be single-sample A8R8G8B8/D24S8 with full color/depth/
stencil clear, depth 1, stencil 0 and a full-target viewport. A target mismatch
is reported at draw/sequence 0. Per-draw failures record both native draw ordinal
and portable event sequence. `CopyPortableHistoryReplay` returns an owned copy
only after the chosen boundary is complete and validated; it never exposes a
partially converted scene as usable history.

## Verification

Both x64 and x86 application builds passed. The new CPU validation, WARP and
hardware CTests all passed on each architecture, with no skips. The GPU cases
draw the fixture through native DX9 and through the converted stream on DX11,
compare complete RGBA images at two prefix boundaries, repeat the first boundary,
and replace the DX11 device. Across the four architecture/driver configurations,
**24 image comparisons have zero differences**. The fixture includes non-white
unlit material, texture color/alpha changes and preservation of old versions.
This is a generated transport/shading control, not a full PMM history comparison.

CPU checks cover invalid layout/base/viewport, fog, point lights, unsupported
texture formats/autogen, truncated bytes, missing state, index range, native
minimum-vertex range, and version overflow. Negative cases leave the existing
resource and event counts unchanged.

Existing versioned-stream validation, both multi-material drivers and the saved
real PMM independent-batch adapter tests also passed on x64/x86: seven focused
CTests per architecture in total. A formats-only Windows build with the DX9 RHI
adapter disabled also built and passed `rhi_model_replay`. This checks optional
backend isolation, not Linux/macOS execution.

## Real PMM capture result

The real `sample.pmm` GUI fixture was rerun with model relocation, single sampling,
material 13 and the original application renderer. The recorder reached 49
preceding draws. The native DX9 prefix comparison reports zero differing pixels
before the selected material. Portable conversion is **BLOCKED at the target
boundary**, because the scene occupies an offset viewport inside the backbuffer:

| Build | Backbuffer | Scene viewport (x,y,width,height) |
| --- | --- | --- |
| x64 | 1920 x 1080 | 565,25,1032,774 |
| x86 | 1920 x 1080 | 274,25,670,503 |

The gate reports `reason=offset_or_partial_viewport`, `draws=0`, `sequence=0`.
No DX11 full-scene image was produced or accepted. Shadow, ground and accessory
conversion is not validated by a failure that occurs before the first draw.
The next contract addition should represent the viewport explicitly, with
full-target readback and depth/stencil coordinates tested, before admitting
those operations. Do not crop the target implicitly or label the 49-draw DX9
comparison as DX11 acceptance.

The GUI harness previously copied history evidence as soon as an unrelated
pixel report appeared. It now waits for the history recorder's own gate. Native
8x acceptance remains unchanged. Portable mode uses exit 31 for rejected or
incomplete conversion; `VALIDATED` denotes transport validation, not pixel
equivalence. Initial manual launch also required the fixture/model environment
variables; missing variables return 77, unrelated to GPU connectivity.

## Reproduce

```powershell
ctest --test-dir build-x64/build -C Release --output-on-failure -R '^rhi_d3d9_replay_conversion'

$env:MDS_PMM_GUI_FIXTURE='C:\Users\jstzw\Downloads\MikuMikuDanceE_v932\UserFile\sample.pmm'
$env:MDS_PMM_RELOCATE_MODEL='Dammy_Bone.pmd'
$env:MDS_RHI_HISTORY_REPLAY='1'
$env:MDS_RHI_PORTABLE_REPLAY='1'
$env:MDS_RHI_REPLAY_SINGLE_SAMPLE_CONTROL='1'
$env:MDS_RHI_REAL_BATCH_CAPTURE='1'
$env:MDS_RHI_GUI_MODE='model'
$env:MDS_RHI_GUI_MATERIAL='13'
$env:MDS_RHI_EVIDENCE_DIR=Join-Path (Get-Location) 'exports/portable-native-prefix-x64'
& ./build-x64/build/Release/pmm_v1_relocation_gui_test.exe `
  (Resolve-Path ./build-x64/build/Release/MikuDanceStudio.exe).Path `
  (Resolve-Path ./build-x64/build/Release/rhi_d3d9_parity_test.exe).Path
```

Substitute x86 paths for x86. Read `history_replay.dx9`, `model_batch.same_frame`
and `d3d_create.attempts.txt` in the evidence directory. Captures/logs are ignored
local artifacts; original PMM/models are not distributed. No new file-format
serialization, DX11 application renderer, MSAA support or portable viewport
mapping is enabled by this change.
