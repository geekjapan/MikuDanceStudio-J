## 数值兼容

2026-10-23 的重构替换或移除了应用中的 14 个内联汇编块，以及本地 Bullet 中的 24 个块（含禁用的备选实现）。裸函数已移除；惯性张量计算改用具名矩阵和向量成员。SSE intrinsic 仍用于需要明确单精度运算的阶段。

`LinearMath/btMmdMath.cpp` 隔离了需要 VC9 x86 求值方式的运算，专用编译选项为：

```text
/arch:IA32 /fp:precise /O2 /Oi /GL- /RTC-
```

这些选项只作用于该编译单元。x64 分支保留自己的表达式和编译设置。修改时须保留：

- x87 的扩展精度中间值，以及通过 `volatile float` 实现的原版浮点写回点。MSVC 的 `long double` 为 8 字节，单改类型不能保留扩展精度求值。
- 有序求和的 `noinline` 边界，以及 sqrt/三角函数的局部浮点控制，避免编译器重新结合表达式。
- 调用方的精度控制和舍入模式，以及归一化、惯性和泰勒展开中明确使用单精度的阶段。

### 数值验证

旧实现与新实现并排比较了 32 种运算：每域 100,000 组输入，涵盖有限浮点位模式、中等指数和定向边界值；组合三种 x87 精度与四种舍入模式。边界包含正负零、次正规数、最大有限值、无穷及 quiet/signaling NaN，未观察到输出位差异。

[数学回归](../../tests/mmd_math_test.cpp) 保留每域、每精度/舍入组合 512 组输入，种子为 `0x191234`，使用 xorshift32 和 64 位 FNV-1a 汇总浮点位模式。[golden 数据](../../tests/mmd_math_golden.hpp) 来自旧实现，不能用替换后的实现重新生成。

x87 `FSIN` / `FCOS` 的近似结果会随处理器变化，定向舍入时不能把某台机器捕获的位模式作为跨 CPU 标准。`sinTimes`、`cosine`、`integrateRotation` 因此使用[冻结的旧实现](../../tests/mmd_math_x87_reference.cpp)在当前 CPU、相同精度和舍入模式下生成对照值；其余 29 种运算继续核对原始 golden。历史汇编仅编译进 x86 测试程序，不链接到应用或 Bullet 库。所有 12 种精度/舍入组合仍逐位核对。

另一次旧/新 Bullet 库对照包含地面、16 个盒/球/胶囊、五个 6DoF 弹簧约束、重力和外加扭矩。三种精度各运行 600 步，逐步比较变换、线/角速度与世界逆惯性，1,800 条帧记录一致。这是固定场景的对照结果，不是所有物理场景的等价证明。

## 帧定位

原 x86 定位入口为 `0x004B4260`，x64 对应入口为 `sub_7FF7CB4EBD90`。显示、表情和骨骼轨道仍按该顺序处理；直接定位从各轨道首键开始，返回最后处理的循环计数。帧号按无符号数比较，骨类型保留有符号字节判断。

选择区间末端分支分别清零 `trans[0..2]` 和 `rotQuat[0..2]`，再将四元数 w 设为 1。原先越过 `trans` 数组边界触及相邻成员的写法已消除，保留六次清零效果。

定位和播放推进不能直接共用一个通用 slerp：x64 定位计算 `sin / sin`，推进路径使用倒数乘法；x86 又有独立的浮点写回阶段。四元数夹取值、符号分支和半圆阈值均须保留。

[定位回归](../../tests/model_frame_seek_test.cpp) 对每架构 880 个场景比较完整骨骼状态、表情值、选择区间、IK 标志、返回值及物理通知发生时的状态与顺序。曲线求值和通知使用确定性测试替身，隔离定位算法。修改前实现的 FNV-1a 基线为：

| 架构 | 汇总值 |
|---|---|
| x86 | `705C9B6BD795F475` |
| x64 | `374EC08163B4FB73` |

上述是纯重构时的旧实现基线。后续原版复核修正了 x64 位置插值，当前 x64 期望为 `76B2F2F248828717`：从未拆分的 `24d8844` 实现出发，仅将该处算式改为原版 `mulss` / `addss` 的单精度阶段后取得；没有从重构后的生产实现重新生成。x86 基线不变。测试另以固定浮点位模式检查三个轴的舍入和负零。

## 帧编辑器

命令分发保留资源编号；内部函数按撤销、范围选择、曲线编辑等动作命名。关键帧复制、粘贴和镜像粘贴移入独立模块，全局轨道注册与编辑器命令分开维护。

三个剪贴板命令及十二个注册相关函数与旧版进行了 C++ 语句 token 对照；除注释、格式、已说明的命名和定位类型接口调整外，语句相同。资源消息顺序、剪贴板布局、分配释放配对和选择循环未改动。剪贴板诊断分支另以 `MIKUDANCESTUDIO_DIAG=1` 在两个架构编译通过。

表情帧编辑使用 `MorphKey` 成员替代手算偏移，保留有符号帧偏移判断、链表遍历、字段写入顺序和未涉及的 padding。

## 场景加载

PMM v2 配置段（原 x86 `0x456617..0x45776E`）拆为时间轴、播放、媒体、显示和物理五个阶段。文件读取、状态修改、同步窗口消息和媒体加载仍交错执行；若先解析全部配置再应用，同步消息处理器可能观察到不同状态。

播放设置与媒体阶段共用一个字节暂存值，显示与物理阶段共用另一个。两者跨阶段保留原值，包括短读取时原值不被覆盖的行为。相机参照模式按原版直接读入成员，不占用播放暂存字节。共享缓冲区仍属于单次加载上下文。

五个阶段的语句分别与旧代码对应区间比较；排除上下文字段绑定和 UI 函数更名后，token 一致。模型加载段只修正旧拆分留下的缩进，读取、重试和中止顺序保持不变。

## 原版 x64 复核修正

随后通过 IDA MCP 及直接解析 PE/x64 指令复核 [基准二进制](../X64_RECONSTRUCTION.md)，确认以下重构前已经存在的偏差，并按原版修正：

| 路径 | 原版指令证据（RVA） | 修正及回归 |
|---|---|---|
| 全局轨道注册 | 相机 `0x5B497` 先比较首记录；灯光、自阴影、重力注册器分别在 `0x5C7B9`、`0x5D069`、`0x5DE09` 同形 | 遍历从首记录开始；已有后续键时第 0 帧覆盖首记录。四类轨道均检查覆盖、后续追加、区间插入、双向链及相对帧号 |
| PMM 分组状态保存 | `0x75877` 按 `0x65` 计算组步长，`0x75886` 比较组内 `+0x64` 的字节，`0x75890 setne` 后写出一个字节 | 保存 `DisplayGroup.flags != 0`，不再读取 `nameEn[0]`。不更改结构布局、文件顺序或 v1/v2 读取侧的 `b == 1` 语义 |
| PMM v2 相机参照模式 | `0x7FFA8` 将一个字节直接读入 app+`0x378`，再更新复选框 | 播放选项恢复移入 [pmm_playback_options.cpp](../../src/io/pmm_playback_options.cpp)，在同步窗口消息前写回成员。测试使用隐藏的真实 Win32 控件，检查消息时状态、原始未知值、后续字段、EOF 和暂存字节 |
| x64 骨骼位置插值 | `0xCD5E8` 为 `mulss`，`0xCD5EC` 为 `addss`；其余两轴同形 | 单精度乘法后加法，保留 x86 原有求值方式。`0.1f → 0.2f`、比例 `0.3f` 的期望为 `0x3E051EB8`，旧 x64 实现为 `0x3E051EB9` |

[全局注册回归](../../tests/global_key_registration_test.cpp)、[PMM 播放选项回归](../../tests/pmm_playback_options_test.cpp)及定位回归的固定数值检查，在修复前实现上均失败，修复后在两种架构上通过。这些用例核查上述行为，未代替原程序完整场景的 GUI / 图像 A/B。

2026-10-24 后续复核保留已经修正的表头遍历，扩展全局注册测试：四类轨道均从 `0 → 10 → 20` 连续覆盖第 0 帧，再追加 30、插入 5，核对全部前后链接；另覆盖非零当前帧下的相对偏移，以及 10000 个槽位占满时覆盖首尾已有记录。覆盖已有帧不经过空槽分配，也不扩大时间轴。

[PMM 分组保存回归](../../tests/pmm_display_group_save_test.cpp) 链接并调用生产模型块 writer，读取实际输出文件，覆盖 0、1、255 个分组、全部 256 种 flags 值及英文名空/非空的组合。按原版 `setne` 检查零写 0、任何非零写 1，同时检查后续字段位置和运行时名称/标志未被修改。模型块 writer 通过 `src/io` 内部头文件声明，保存入口和测试使用同一份编译实现；没有启动模型加载器或原版 GUI，不将文件字节检查称为完整工程往返 A/B。

## Track 相机与模型切换

2026-10-24，针对下游 issue #24 核对原版 x86/x64 后，修正 [SetupFrameWorldTransform](../../src/render/debug_geometry.cpp) 中的参照点选择和父骨骼旋转，并在 [模型选择事件](../../src/window/command_frame_edit.cpp) 中补回焦点恢复。二进制身份采用 [x64 重建基准](../X64_RECONSTRUCTION.md) 中的 v9.32 文件。

| 行为 | 原版证据 | 移植修正 |
|---|---|---|
| 模型编辑的视角参照点 | x86 `0x46B2CF`；x64 RVA `0x277F8..0x27991` | 相机模式使用相机目标/父骨骼；模型模式仅在 Track 且播放中或选中父模型时走相机路径，其余按参照模式使用模型中心、所选骨骼或原点。仅父骨骼相机路径写回 eye |
| 父骨骼旋转 | x86 `0x46B91F`；x64 RVA `0x27A80` | 将骨骼矩阵的 3×3 部分转置，不直接复制，不改写保存的自由视角基 |
| 无可用父级变换 | x86 `0x46BAB1`；x64 RVA `0x27C72` | Track/相机模式下无父模型或变换被抑制时，将保存的 CameraAttachmentBasis 写回单位矩阵；自由视角继续使用保存的基 |
| 模型下拉框焦点 | x86 `0x4828D5` 调用选择函数后跳至 `0x48F2DA SetFocus`；x64 对应 RVA `0x52C77`、`0x53DE0` | 在控件 436 的 CBN_SELCHANGE 且模态门控允许时，选择完成后 SetFocus(主窗口)，避免下拉框继续接收方向键 |

`PostModelReload` 的视角补偿保持原版语义：原版 x64 RVA `0x72B06/25/39` 分别写回 X/Y/距离；独立执行该函数的原始机器码后，七个固定场景与当前补偿结果一致。不能以清零编辑偏移替换这段补偿，也没有向 PMM 成功加载尾部添加无原版依据的相机重置。

[相机矩阵回归](../../tests/camera_world_transform_test.cpp) 链接生产库，在无窗口、无 GPU 的设备替身上捕获实际 world/view 设置。19 个场景覆盖相机/模型模式、Track 开关、播放、父模型选择、三种参照点、无骨骼选择、变换抑制和保存的旋转基，检查矩阵、eye 状态、保存的基及设备调用次数。矩阵比较容差为 `1e-5`，固定输入的 eye 状态精确比较。前七个场景的期望来自执行原版 x64 RVA `0x2767B..0x28010` 的实际机器码，D3DX 运算使用本机 DLL；其余用例根据同一段原版分支和精确的 90° 矩阵设置期望，不从移植实现反向生成。

上述回归在修复前的 x86/x64 库上均失败，修复后均通过。七个原版机器码场景的最终 World×View 最大元素差由原来的 `0/0/13/18/26/26/26` 全部降为 0。此结果验证覆盖场景的矩阵和状态，没有复现报告者 PMM 的完整操作链，也未进行真实下拉框键盘交互或 GPU 图像 A/B。

## 最近运行结果与限制

2026-10-24，原版复核修正后，本地 x64/x86 Release 构建完成，完整测试分别为 48/48、47/47 通过，包含新增注册与 PMM 回归、D3DX 运行时和 GPU 测试。早前的会话环境失败见 [D3D9 / D3DX 调查](d3dx_runtime_failure.md)。

上述结果验证了覆盖场景下的修改前后行为；本轮未重新进行原版 MMD 的逐帧 GUI/图像 A/B。完整验证范围见 [移植状态](../PORTING_STATUS.md)。

同日的分组保存跟进完成两架构 Release 完整构建及专项反向验证：重现旧表头遍历和错误字段读取时，两项测试均失败，恢复后均通过。此次完整 CTest 分别为 x64 41 通过/7 跳过/1 失败、x86 40 通过/7 跳过/1 失败；失败和跳过均发生在原生 D3D9 设备不可用状态，具体 HRESULT 与构建隔离方式见移植状态。本轮没有更改设备创建或测试跳过策略。

Track 与模型焦点修正后，本地 x64/x86 Release 再次完整构建，19 个相机矩阵场景及现有输入序列、PMM 回归均通过。当前配置下完整 CTest 为 x64 42 通过/9 跳过/1 失败（52 项）、x86 41 通过/9 跳过/1 失败（51 项）。失败仍是 `mme_d3dx_runtime` 的原生设备创建：`CreateDevice(NULLREF)=0x8876086C`，原生 HAL/NULLREF 能力查询均为 `0x8876086A`；没有绕过或改写该测试。
