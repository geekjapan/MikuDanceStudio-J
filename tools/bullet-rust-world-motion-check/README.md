# Bullet world motion passes

Run `python3 tools/bullet-rust-world-motion-check/check.py --out-dir /absolute/fresh/evidence`.
Use `python3 -O -m unittest discover -s tools/bullet-rust-world-motion-check -p 'test_*.py'` to check optimized Python acceptance boundaries.

The twelve controlled-command acceptance cases run through `check.main()` with actual-host and simulated Windows x64 views under normal and optimized child Python. The Windows mock supplies an MSVC `native-static-libs` diagnostic and checks both native link commands receive its libraries. Only the checker's OS view is replaced, preserving host filesystem paths. This is helper coverage; actual Windows MSVC execution remains required.

The native oracle includes both unchanged shims in separate translation units. Protected world passes and local time are accessed through base-class member pointers, without a derived-object cast or native header modification. The Rust replay uses the actual `WorldObjects` owner and its captured registration order.

Each public/MMD replay has four transform variants and eighteen snapshots. It captures complete body, interpolation, motion, inertia, force, torque, activation, filter, hit fraction and registration state. The 1,368 records cover static and kinematic registration, later kinematic changes, active/sleeping/disabled bodies, zero and nonzero timesteps, damping, distinct interpolation velocities, all/default synchronization, three hit fractions, and teleport/reseat/stop interleaving. Rotations include nonunit quaternion input and all matrix extraction branches. One MMD variant uses finite invertible nonorthogonal matrices to distinguish matrix inverse from transpose.

Twelve controls compile and execute altered Rust implementations. They must emit schema-valid traces that differ from native. The checker records source membership/hashes, generated source membership/hashes, actual compiler include membership/hashes, commands, versions, flags, macros, raw traces, observer traces, and mutation results. Command and acceptance boundaries use explicit runtime errors under normal and optimized Python. Start/end/finally closure comparisons fail closed.

The four supported host jobs run native differential checks. Workflow configuration is not executed CI evidence. No numeric tolerance or host profile is approved by this checker. Public World/PhysicsScene cutover, the step scheduler, broadphase, islands, callbacks and GPU execution remain outside this unit.

The activation owner extension appends `AP` and `AM` records after the unchanged motion segment. The checker pins the original 1,368 records and 144 snapshots by SHA256 `b335376402a05fbeb89b24071fd3e189c4270b5fdcbe978d2e5df3ab5a1479d4`. Its original activation schema remains 1 through 5. Only activation segment body records accept Moving 0 through DisableSimulation 5. Additional `A` records expose current classification, deactivation time and both sleep thresholds.

Thirteen scenarios per constructor each capture five snapshots. Empty public and ground-only MMD owners are included. Populated scenarios capture actual constructor defaults before seeding states 0 through 5, independent motion/interpolation/force/inertia/hit-fraction sentinels, static and kinematic registration, dynamic registration followed by kinematic toggling and return, and MMD mode 0. Floor flags alternate between 1 and -1. Calls include zero and positive dt, repeated accumulation, default/custom/disabled/zero-time settings, and below/equal/above deactivation and linear/angular sleep thresholds. Sleeping dynamic bodies zero both velocities; WantsDeactivation keeps them. Protected states 4 and 5 remain protected. Inputs are finite; no undefined float-to-integer conversion is used.

Twelve additional controls modify generated copies of the owner or existing activation kernel. They test captured membership, active/dynamic filtering, zero-dt early return, omitted kernel and velocity writes, supplied settings, strict time comparison, protected setters, and sleeping/WantsDeactivation zeroing. All 24 controls must compile, execute, emit schema-valid output, and differ from the native trace. Compiler failure, panic and malformed output cannot count as catches. No activation kernel or public bridge source is changed. The Windows stderr transport correction remains a separate integration dependency.
